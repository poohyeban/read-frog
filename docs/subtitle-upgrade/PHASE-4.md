# 调度、失败与质量

- 复用RequestQueue：字幕队列启用0当前/1即将播放与当前分段/2预读/3摘要与导出优先级。每等待30秒改善一级，长期辅助请求不会因持续新字幕永久饥饿；scheduleAt、429暂停、token bucket、超时、取消引用计数仍生效。已执行请求不抢占。网页队列不启用优先级扫描。
- 内容侧最多2批×5条、分段1个；按播放速率1–4倍扩大窗口。字幕BatchQueue保持100ms聚合，然后进入可排序的网络队列；取消原先等待网络空位才flush的门槛，避免当前字幕卡在已排队摘要之后。网页批处理门槛保留。后台等待队列跨任意数量标签仍没有全局硬上限；每个生产者有界。
- 失败结果区分成功、合法空文本、暂时、永久、取消。成功邻居保留；临时失败保留原文并冷却至少30秒或Retry-After，最多一次额外恢复；永久失败等待显式重启/配置变更。已有网络队列仍先执行自己的有界重试。失败不写成功缓存。
- 配置watch只比较翻译语义：Provider、语言、模板、分段、上下文、术语开关；术语revision独立watch。修改后取消旧会话、清除旧译文、保留原文并从当前时间重启。样式编辑不重启。导出会话独立；停止也取消正在等待config/source准备的启动代次。
- 摘要根据选中模板的实际VIDEO_SUMMARY依赖生成，不阻塞播放。已发出批次复制上下文，晚到摘要仅供后续批次；原有上下文采样不变。摘要缓存纳入标题，分段缓存纳入实际Prompt、校验规则版本和16384输出预算。16384是本次显式补齐，旧代码有专用预算注释但未传值，不能宣称旧实现已保证同值。
- TextTrack缓存纳入轨对象身份及完整cue内容摘要；相同标签的新轨和同数量原文编辑不会复用旧字幕。哈希只在轨检查调用，不在timeupdate。cleanup使尚未完成的cue轮询在下一个有界轮询步退出。

验证：70文件648测试通过；后续配置/原生轨专项4文件64测试通过，调度收敛专项3文件54测试通过（这些集合有重叠，不相加）。最终全套结果见最终报告。没有真实Provider调用或收费压力测试。
