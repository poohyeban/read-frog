# Read Frog Lite 0.2.3

修复字幕等待状态、扩展更新后的旧脚本清理，以及 AI 断句的时间轴校验。不增加依赖、浏览器权限或云端通信。

## 本版修复

- 长字幕在开始播放数秒后仍然有效；拖动进度到其中段时也会进入翻译队列，不再由于开始时间落在回看窗口之外而永远等待。
- 翻译失败使用本次请求已取得的配置完成回退；不在错误处理里再次读取可能已经失效的扩展存储。
- 扩展更新 / 重载后，在视频更新和页面可见性变化时清理旧字幕会话，恢复原生字幕。主题刷新处理存储读取失败，避免每次切回页面都产生未捕获 Promise 错误。
- AI 断句必须保留原文顺序和完整片段，时间边界必须对应这些片段，不能跨越长静音。允许调整大小写、标点、空白；错位、缺失或改写结果使用现有本地断句回退。
- 后台写缓存前、读旧缓存时，以及内容脚本使用断句结果前均校验。错位旧缓存自动删除并重新生成，不要求清空 Key 或所有本地数据。

## 验证与边界

新增单元回归覆盖长字幕跳转、存储失效、停止期间的异步结果、主题切页刷新、AI 时间单位 / 相对时间 / 错误句界 / 文本归属 / 缺失 / 重复，以及旧缓存失效和本地回退。

生产 Chromium 浏览器回归使用本地 HTTP 模型和可控 YouTube 页面，执行真实拦截器、字幕下载、翻译队列、SDK、存储与渲染。覆盖连续 21 条字幕、长字幕中段跳转、扩展重载后切页、刷新恢复，以及正确和偏移 10 秒的 AI 结果。[最终 CI](https://github.com/poohyeban/read-frog/actions/runs/40859329633) 已通过：类型 / Lint、269 个测试文件中的 2601 项测试、Chromium 生产 ZIP，以及两项真实浏览器回归。字幕回归的页面未捕获异常为 0；正确 / 故意偏移 10 秒的 AI 响应各验证了 6 条字幕。构建信息记录在 `final-metrics.json`。

尚未验证用户账户的真实 DeepSeek 延迟与返回内容，也未把模拟播放器结果当作当前线上 YouTube / Netflix / X 的兼容性证明。无法从截图还原该视频当时的原始 AI 响应，因此本版修复已复现的错误路径，不声称已证明那一次偏移的唯一原因。模型改写原文时会回退本地断句；原始字幕本身的时间错误仍需平台数据层另行定位。

“翻译中”随后正常完成通常是服务延迟；本版保留现有请求超时，不以提前终止请求掩盖等待。`Receiving end does not exist` 的后台消息问题已独立定位，本版未修改它。

## 安装 / 更新

下载本 Release 的 `read-frog-lite-0.2.3-chrome.zip`，解压后加载含 `manifest.json` 的目录。已有安装请保留原目录和扩展 ID，替换文件后在扩展管理页重新加载，**再刷新已经打开的视频页**。不需要删除配置或重新填写 Key。
