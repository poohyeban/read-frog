# 真实 MV3 发布前人工验收

本轮状态：**未完成，受管理策略阻断**。单元测试、浏览器页面夹具、Provider mock 均不能替代以下验收。2026-10-30 的只读预检记录见 [release-boundary/mv3-preflight.json](release-boundary/mv3-preflight.json)。

## 环境与证据

1. 使用明确允许 unpacked 扩展的个人或测试用 Chrome / Chromium。先在 `chrome://policy` 查看实际生效策略；遇到扩展安装限制立即停止，不删除策略、不换浏览器绕过组织限制。记录浏览器版本、OS、提交 SHA、扩展版本和配置摘要，勿记录 API 密钥。
2. 在仓库运行 `pnpm exec wxt build`。打开 `chrome://extensions`，在允许的环境开启开发者模式，加载 `.output/chrome-mv3`。记录扩展 ID 和权限。使用测试配置及可授权使用的 Provider。
3. 自动化预检：`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium node e2e/mv3-preflight.mjs`。状态 `available-not-accepted` 只证明该扩展的真实 MV3 Worker 可加载，不代表以下场景通过。退出码 2 表示阻断或环境不可用。
4. 可复现的原生扩展夹具：`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium pnpm exec playwright test e2e/extension.spec.ts e2e/subtitles.spec.mjs`。字幕夹具使用真实扩展、消息、队列及 SDK，但 YouTube 播放器和模型响应受控；不能替代真实站点、登录、广告和自然 Worker 休眠。`MV3_HEADED=1` 可显示字幕夹具浏览器。
5. 每项记录操作前后视频时间、轨道、Popup 状态、实际字幕、请求开始/取消/结束和截图或 trace。导出记录文件 SHA256、cue 数、首末时间戳。日志脱敏。失败、不可执行和通过分别记录，不把不可执行算通过。

## 缓存专项复核

使用可记录输入的本地 Provider 或测试账号，准备 A、B、C 三条字幕，给 A/B 设置不同术语。先请求 `[A,B]`，重复相同批次应命中缓存且无模型请求；改为 `[A,C]`、`[A]`、`[B,A]` 应按实际新批次请求。令 `[A,B]` 连续返回错误条数，验证有限重试后单项回退各自使用自己的术语；恢复批量服务后不得把单项回退结果拼成批量缓存。修改术语、摘要、模板和模型后按新 Prompt 获取结果。

本轮未新增关闭批处理、缩短上下文或移除术语的策略。缓存以实际整批 Prompt 为边界，批次划分改变会降低跨批次命中率，这是避免错误复用的必要取舍。
